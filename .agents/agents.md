Вот распознанный текст с изображения (техническое задание на проект по машинному обучению):

1. Организация кода и контроль версий (Git)

Создайте структурированный репозиторий на GitHub (например, используя шаблон cookiecutter-data-science).

Код должен быть хорошо организован в модули (папки src/, notebooks/, data/, models/ и так далее).

Используйте осмысленные коммиты.

2. Подготовка и валидация данных:

Напишите скрипт для загрузки и первичной очистки данных.

Реализуйте этап Feature Engineering (например, создание агрегированных признаков из истории платежей, бининг возраста).

Обязательно: используйте Great Expectations или Pandera для создания набора правил (suite) для валидации входящих данных (проверка на наличие пустых, ожидаемый диапазон значений, типы данных). Напишите тест, который провалится, если в новых данных появляется аномалия.

3. Построение и настройка модели

Разделите данные на тренировочную и тестовую выборки.

Создайте sklearn Pipeline, который включает в себя этап предобработки (Imputer, Scaler, OneHotEncoder) и обучение модели (например, LogisticRegression или GradientBoostingClassifier).

Реализуйте автоматический подбор гиперпараметров с помощью GridSearchCV/RandomizedSearchCV.

Обязательно: выведите ключевые метрики качества для задачи бинарной классификации: ROC-AUC, Precision, Recall, F1-Score на отложенной тестовой выборке. Постройте ROC-кривую.

4. Экспериментирование и логирование

Обязательно: интегрируйте MLflow Tracking в ваш код обучения.

Записывайте в MLflow: параметры модели, метрики, артефакты (включая графики, такие как ROC-кривая, и саму обученную модель - mlflow.sklearn.log_model).

Проведите как минимум 5 экспериментов с разными алгоритмами и/или гиперпараметрами, проанализируйте результаты в UI MLflow.

5. Контроль версий данных и моделей:

Обязательно: инициализируйте DVC в репозитории.

Настройте DVC для управления версиями датасета и обученных моделей. Конфигурация должна быть описана в dvc.yaml.

Реализуйте DVC-пайплайн как минимум из двух стадий: prepare (подготовка данных) и train (обучение модели).

6. Тестирование (CI)

Напишите unit-тесты (с помощью pytest) для ключевых функций вашего кода (например, для функций предобработки, вычисления метрик).

Настройте GitHub Actions для автоматического запуска этих тестов и проверки качества кода (линтеры и форматирование с блоком при каждом пуше и пулл-реквесте).

Обязательно: включите в CI-пайплайн шаг, который запускает валидацию данных с помощью Great Expectations.

7. Контейнеризация и развертывание:

Напишите Dockerfile для создания образа вашего приложения. Образ должен содержать все зависимости для запуска обучения или инференса.

Обязательно: реализуйте простой REST API для модели с помощью FastAPI. API должен иметь эндпоинт /predict, который принимает JSON с признаками и возвращает предсказание (класс и вероятность).

Напишите скрипт для быстрой сборки-образа и его запуска локально. Убедитесь, что API работает.

8. Мониторинг (CD)

Разработайте минимальный скрипт для генерации синтетического сдвига данных (например, Population Stability Index (PSI) для распределения вероятностей или для ключевых признаков) при сравнении с тренировочными данными.
